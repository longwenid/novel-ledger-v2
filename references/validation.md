# 验证方法与证据分层

运行 `python3 -m unittest discover -s "$ROOT/tests" -v`。测试使用临时项目和标准库，不访问模型或网络。

工程验收关注：幂等、事务原子性、版本和租约绑定、修订传播、资源守恒、误信独立、伏笔生命周期、检索来源、上下文规则有界、崩溃不重复派发，以及固定地址/用途搬迁、路径耗时、感知条件、持有链和稳定特征保护。用千章合成事件检查长历史，不把它叫作千章小说实写。

空间回归还覆盖第一章确立四楼101、后文错误三楼505、合法重编及历史地图。独立验证记录与局部地图导出见 `validation/`；地图提示并不能识别所有跨句指代，语义缺陷须由事实审稿发现。

分层设计测试覆盖全书/分卷/近期任务顺序、两卷完本、设计历史与修订失效、必需材料容量、场景任务书和角色输入隔离。`validation/layered-brief.md` 为实际派发的写作输入示例，独立 CLI 日志使用合成审稿，不能混入文学质量结论。

人物模块验证角色资料选择、档案来源与版本、成长重审、历史修订、静默场景、对白缺陷进入返修，以及首读材料隔离。`validation/character-brief.md` 为实际任务生成的输入，工程回执不代表文学质量。

局部返修验证不可变基稿、中文字符位置、重复片段、多补丁偏移、错版本/错位置/重叠拒收、事务不变、重复提交、片段读取、上下文扩大及历史原稿复用。补丁合成后必须重跑完整 facts/reader。字符数与 JSON 体积只表示重复材料减少，不能冒充实际模型 token 或费用数据。发布前另检查完本后的分支修订及重新完本，发布包解压后运行同一测试集。

分卷篇幅测试检查初始化合计、只统计有效正文、短卷释放剩余空间、预算超支提示、候选分支隔离、整数分配守恒与读者首读隔离。分卷预算不代替全书篇幅验收，不把参考量当作单卷必须填满的配额。

真实创作试验另存于 `validation/`：一部十二章的压缩测试故事、跨题材短样、实际任务/审稿记录，以及与旧指导下短样的对照。测试书故意采用小篇幅以验证完整闭环，不套用正式百万字合同；它不能证明百万字成书质量。

比较时固定创作题目和目标体验，隐去版本标签，评估追读、人物、兑现、语言和重复；判断必须引用具体正文。应披露是否同模型、是否完整旧流水线、是否真正独立上下文以及是否人工评价。没有这些条件就标局限，不宣称统计意义上的优胜。

跨模型使用是协议设计目标。实际兼容表记录宿主/模型、日期、操作、结果和缺失项；未接入其他服务时写未验证，禁止用模拟 driver 测试冒充跨厂商实测。

开发中的性能、工程通过率与文学评价分开报告。修复只根据复现缺陷或具体读感问题落地，不因一例反馈无限添加通用禁令。

## 有界上下文验收

执行 `validation/context_endurance.py --out <结果JSON>`：五组千章合成历史，分别施加认知累积、伏笔积压、远期全文依赖和人物档案负载，经持久化扫描/归并、重启、实际 draft/facts/reader 提交第1001章。检查实际 input.json 长度、回执容量计量、旧正文不变，不能把合成判断当成真实千章写作。另覆盖失败回执计量、无效 driver 输出、补读累计计量、真实会话交接协议、来源伪造与归并漏源拒收；实际宿主窗口与文学效果另测。旧用例显式 legacy 仅复现历史行为，新上下文用例必须 bounded。
