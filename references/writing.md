# 场景写作
何时读：执笔/返修 Worker 场景写作、篇幅与章末收束。

执笔与返修遵守 [声线通用规则](voices.md)，不靠修饰补篇幅。

每次只处理当前信封，读取最新 input 后执笔；提交后由主控调度下一任务。会话复用与写审分工见 [runtime](runtime.md)。

## 场景构建与任务书落实

- **依任务书执笔**：以输入包的 `writer_brief`（场景任务书，详见 [分层设计](design-and-brief.md)）为基准，明确场景目标、人物选择与必要转折。
- **尊重时空事实**：行动前核对人物所处场所 ID、出口、遮挡与携带物件（详见 [空间与稳定事实](spatial-continuity.md)）。
- **杜绝信息透支**：严格区分作者设定、读者视角与当前人物知情边界；未经正文发生或获取的情报，角色不得擅自知晓。
- **避免流水账扩写**：场景不是逐条翻译大纲，允许人物动作、试探与误判产生具体细节；新增重大事实由综合审稿的 facts 子回执如实提取。

## 首稿篇幅与章内呼吸

先看 payload.chapter_length 与 writer_brief.execution。目标以作者约定和事先章纲为准，不是截断上限；未设目标时不擅设门槛。

按 expansion_units 演出试探、误判、策略改变、选择代价和后果，不把一句大纲扩成同义解释。关键选择给足动作、停顿、潜台词与阻力；无变化的赶路和重复确认略写，不套固定事件数或顺序。

rhythm 指向本章作用和压力变化。呼吸可处理后果、关系、损失与下一步选择；舒缓仍有进展，持续高潮可保持紧绷，不生插闲聊或定时强加危机。

写好结果文件并自查后直接执行信封的 `commands.submit`。程序按全文或补丁合成稿计算实际汉字，篇幅不足时保留短稿并返回定向返修所需的缺口，不下调目标；达标后继续独立综合审稿。

需在提交前确认计数时，可选只读预检，不重复向模型加载正文：

```bash
python3 "$ROOT/scripts/novel.py" measure --project "$PROJECT" --result <output_path>
```

读取 actual_han/target_han/shortfall_han，不足时补实未演出的阻力、选择和后果。补丁按合成全文计数；达标后仍删除重复，不复述设定或添加无因果事件凑字。对篇幅拿不准时提前预检，可减少短稿触发额外返修的开销。

## 人物表达与声线差异

- **差异化声线**：存在 `character_context` 时（详见 [人物档案](characters.md)），按角色小传与当前意图说话；各人话语策略与利益诉求必须有区别，禁止千人一面。
- **认知驱动行为**：人物行动必须基于其持有的证据和认知（`knowledge`）；允许角色因误信做出决策，但必须有情报来源。
- **行为代价落地**：角色的选择必须产生可见后果（人际变动、资源损耗、伤势状态），不写无代价的机械升级。

## 收束形态与文风治理

- **章末收束**：按章计划中的 `ending_shape` 收束；悬念钩子非必要不添加，章末优先落在动作、决定或后果上；禁止生硬切断，账本钩子只为已确立的真实承诺登记。
- **文风锚点**：按 style_anchor.traits 的语调、节奏、句式和词域写作，language 核验表达，voice_match 核验声线连续性。
- **局部修改原则**：返修优先按 [局部修订](repairs.md) 提交段落补丁，保持未改部分原文原样，避免整章反复重刷。

## 题材硬约束

- **仙侠/玄幻**：境界、资源消耗、修炼时钟与功法代价严格匹配账本。
- **都市/职业**：利益机制与决策逻辑自洽，行业规则不随意胡编。
- **科幻/奇幻**：核心设定与能力边界全局有效，不靠临时机械降神脱困。
- **悬疑/推理**：关键线索必须前置呈现，答案能从已有正文回溯验证。
