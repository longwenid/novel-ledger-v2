# 事实、阅读体验与完本审查

## 事实阶段 facts

通读当前正文，读取相关原文和当前账本；既检查计划结果，也发现计划之外的人物、承诺和资源变化。

基础检查项为 `coverage / continuity / resources / knowledge / time / world_rules`；登记稳定事实或空间信息后增加 `stable_facts / spatial`，以本次 `payload.checks` 为准，每项给结论、理由和正文证据。`coverage` 特别核对“有没有已发生但漏登记的变化”；不相关项目明确给 `not_applicable` 理由，不能用一句套话覆盖所有项目。

涉及地点、移动、物品交接、感知或稳定外貌时，按 [空间核验](spatial-continuity.md) 比对原始证据和当前布局；检查跨句指代，不只响应自动地址提示。

pass 另需 events 与章摘要。引文精确支持结论，理由解释因果，摘要覆盖选择、后果与未决压力；省重复，不省证据和分歧。程序校验不替代语义判断。

profiled 模式增加 character_consistency，核对经历/认知/动机与成长因果；提取重要变化的 character_development 事件，见 [人物审查](characters.md)。

## 读者阶段 reader

先只读正文和本章任务，不读执笔自评或事实审稿结论；记 first_read，再 recall --contract 核对承诺。同会话须标 serial，不称盲审。

first_read 包含 desire/obstacle/change/read_on_reason。检查项以 payload.checks 为准，reason 解释阅读影响，pass 的 findings=[]。

有篇幅目标时检查 substance：正文是否产生有效动作、信息、选择、关系或代价变化，是否以重复解释、标签或同义对话充数。不按字数达标或事件数量判质量。

language 按 [声线通用规则](voices.md) 核验非必要修饰和情绪标签，给原文位置、缺少的作用与修改目标；不按词数、比例或禁词机械判定。跨章复核检查同类问题是否反复。

声明节奏时检查 pacing：压力变化有无原因，重要选择是否被跳过，后果是否充分消化，缓处有无未决期待。指出失衡语段和阅读影响；不强制高潮休息、静章加危机或固定松紧比例。

发现须解释具体机制，如“角色无代价达成目标，削弱抉择压力”，不能只写“张力不足”。

profiled 模式增加 dialogue_identity：判断不同人物的关注点、关系立场和话语策略是否在正文中成立。先首读，之后再查小传来源；无对白可具体说明不适用，不能强行加对白。

发现分 `blocker`（事实/完整性故障）、`quality`（实质影响阅读）、`note`（可保留的轻微建议）。前两类触发 fix。不要把个人偏好当质量缺陷；允许克制、缓慢、复杂或留白，只要服务本书并能被读者接住。

定点缺陷给 repair_scope=local，整章因果问题用 chapter，见 [局部修订](repairs.md)。补丁后审完整新章，重核证据位置。

每次修改重新两审，旧稿与回执留存。返工上限见 [核心规则](../SKILL.md)；偏好争议须给可检验的阅读影响。

## 十章、卷末及全书复核

代码可定位已选证据、计数和写出已判断的回执，不得批量造 pass、套理由或任取引文。

跨章 pacing/repetition 对照正文与各章职责，核对无变化升级、无因果重置、余波遗漏和连续舒缓的推进。plans 供对照，以正文为准；举证重复机制，不按章末类别轮换验收。

profiled 模式的整体复核增加 voice_evolution，检查声音同质化、无依据的人设突变、情绪重置和合理成长是否持续。存在 `style_anchor` 时 reader 审稿增加 voice_match：对照锚点 traits 与样例段，核对叙事口吻、句式节奏与用词域是否连续，必须有正文证据；声线漂移不是禁词问题，是换了叙述者。

`*_chunk` 提供全文、版本绑定与按章号索引的 plans，覆盖全部有效章节。正文按 prose_files 每章一个内容寻址文件交付，字节与任务 branch 的各章库存正文一致，证据坐标以对应章文件内容为准；含旧式分隔标题【第N章】的引文仅在剥离后唯一命中时可重定位。export/html 默认 active 分支，核对工作分支时显式 --branch。

整体任务不附单章计划，接收分段结论、发现和 chapter/start/end/source_hash 指针；用 recall --chapter N 补读原文，必要时 context_more。核对跨段因果、人物弧、承诺、节奏、规则和重复，不一次加载全书。

整体 pass 需 memory，提炼局面、关系和未决压力，附正文来源，不拼接全部章摘要。全书另查 ending/length/core_promises。

整体卷审 volume_development 使用同名 payload 的职责、实际汉字数、预算、全书余量、后卷职责和本卷设计，核对关键交锋、选择、代价与余波。偏离预算须说明结构原因和后卷承载；重要过程被跳过则举证修订，不机械补字。无预算仍查展开；旧 pending 按冻结检查项，旧已通过卷审不自动补做。

发现影响后文的问题，系统自动建立修订分支，从最早受影响章重新写作/核验至原有章尾，原本无需修改的章节可原样提交但须重新核验。在修订范围外不得假装修好；已发布章节不自动改写。整段修订连续失败超过两次暂停，保留证据。

整体发现标 repair_route：表达类用 patch 定点修改，事实/因果/认知/时间类用 revise 重验受影响后缀。reuse_original 与免审条件见 [protocol](protocol.md)。表达补丁仍核对否定、说话人、来源、时间和因果；自动续算的事件若语义已变，用 prior_dispositions 替换或删除。

## 完本和覆盖边界

`complete` 校验实际汉字数、所有卷审、全书终审、重要承诺关闭、事件链及正式正文。章数达到计划、模型说“完结”、或一份摘要审稿通过，都不是正常完本。

交付正文、章节清单、审计结果和非阻断建议，注明模型/宿主、审稿独立性及覆盖范围。
