# 事实、阅读体验与完本审查

## 事实阶段 facts

通读当前正文，读取相关原文和当前账本；既检查计划结果，也发现计划之外的人物、承诺和资源变化。

基础检查项为 `coverage / continuity / resources / knowledge / time / world_rules`；登记稳定事实或空间信息后增加 `stable_facts / spatial`，以本次 `payload.checks` 为准，每项给结论、理由和正文证据。`coverage` 特别核对“有没有已发生但漏登记的变化”；不相关项目明确给 `not_applicable` 理由，不能用一句套话覆盖所有项目。

涉及地点、移动、物品交接、感知或稳定外貌时，按 [空间核验](spatial-continuity.md) 比对原始证据和当前布局；检查跨句指代，不只响应自动地址提示。

事实核验的 pass 还需提交 `events` 与不超过 1600 字符的章摘要。摘要是导航，写本章选择、后果、未完事项，保留正文事件证据。程序验证资源前值、状态迁移和引文；引文真实不证明推论正确，语义审查不可省略。

profiled 模式增加 character_consistency，核对经历/认知/动机与成长因果；提取重要变化的 character_development 事件，见 [人物审查](characters.md)。

## 读者阶段 reader

先只读正文和前提明确的本章任务，不读取执笔自评或事实审稿的结论。记录 `first_read`：人物想要什么、实际阻碍、章末变化、想或不想继续读的原因。再用 `recall --contract` 补读创作约定，判断本书承诺是否被兑现。单会话不具备真正遮蔽历史条件，记录 serial，不能自称盲审。

检查项为 `read_on / character / change / emotion_cost / language / repetition`。目标是阅读体验，不是审查是否逐条执行作者指令。举例：

- 不合格：“张力不足，建议加强。”
- 有用：“第三段替主角解释信任，随后他无代价交出证据；读者没有见到选择为何难。让他承担一项可见损失，并让对方的反应改变关系。”

profiled 模式增加 dialogue_identity：判断不同人物的关注点、关系立场和话语策略是否在正文中成立。先首读，之后再查小传来源；无对白可具体说明不适用，不能强行加对白。

发现分 `blocker`（事实/完整性故障）、`quality`（实质影响阅读）、`note`（可保留的轻微建议）。前两类触发 fix。不要把个人偏好当质量缺陷；允许克制、缓慢、复杂或留白，只要服务本书并能被读者接住。

定位明确、无需整章因果重排的缺陷，在 fix 回执中给 repair_scope=local，按 [局部修订](repairs.md) 只重写相关段落；整章问题用 chapter，不能为了省 token 缩小真实问题。补丁合成后仍审完整新章，不能复用旧证据位置。

定点修订最多两轮，然后 `redesign` 重审设计、说明改动并重写一次。每次修订都重新事实审查与读者审稿，旧稿和审稿回执保存在任务历史。若观点争议不依赖客观矛盾，给出可检验的阅读影响，避免来回推翻形成无限循环。

## 十章、卷末及全书复核

profiled 模式的整体复核增加 voice_evolution，检查声音同质化、无依据的人设突变、情绪重置和合理成长是否持续。存在 `style_anchor` 时 reader 审稿增加 voice_match：对照锚点 traits 与样例段，核对叙事口吻、句式节奏与用词域是否连续，必须有正文证据；声线漂移不是禁词问题，是换了叙述者。

程序逐章派发 `*_chunk`，提供全文并记录版本绑定，确保所有有效章节均被覆盖。正文证据以各章库存正文为坐标系：分段视图中的【第N章】章头只是分隔，不属于正文，quote 不要包含它（含章头的引文会被引擎剥离后重定位，能唯一命中方可通过）；坐标属于任务 `branch` 字段所指分支的库存正文，`export`/`html` 默认输出 active 分支，与工作分支可能不同，须显式 `--branch`。`recall --chapter N` 只返回正文与摘要；审稿任务的补读配额按所审正文体量声明（`retrieval_allowance`），通读所审范围不必也不应绕开计量直读导出文件。`*_chunk` 工作包含所审各章自己的计划（`plans`，按章号索引），据此核对每章是否落实其目标、阻力与变化；整体复核不附单章计划。随后派整体复核，核对跨段因果、人物弧、承诺、节奏、规则与 repetition——跨章重复用语、同款收束与段式复用，用 recall 对照此前章节举证。整体任务收到的分段材料只含各段结论与发现（证据指针为 chapter/start，引文原文按需 recall），可以分批 `recall` 查证，不要求把全书塞进一个上下文。

整体报告需 `memory`，最多 2400 字符，提炼目前真正改变的局面、关系与未解压力，附正文来源；不能把全部章摘要再拼一遍。全书检查另含 `ending / length / core_promises`：结局是否完成约定的事实、人物是否承担前面选择的后果、核心承诺是否兑现。

发现影响后文的问题，系统自动建立修订分支，从最早受影响章重新写作/核验至原有章尾，原本无需修改的章节可原样提交但须重新核验。在修订范围外不得假装修好；已发布章节不自动改写。整段修订连续失败超过两次暂停，保留证据。

v1.13 起修订传播按性质定界：整体复核发现应标 `repair_route`——**表达类**（重复用语、收束同质化、节奏、声线）标 `"patch"`，只定点修改被点名的章（其余章 `reuse_original` 逐字相同即免复验直接提交，不再为纯表达问题级联全后缀）；**事实/因果/认知/时间类**标 `"revise"`，从最早受影响章修订并重验后缀。判断标准：改这一段会不会让任何已登记事件需要变化——不会，就是 patch；会，就是 revise。

## 完本和覆盖边界

`complete` 校验实际汉字数、所有卷审、全书终审、重要承诺关闭、事件链及正式正文。章数达到计划、模型说“完结”、或一份摘要审稿通过，都不是正常完本。

最终交付：正文导出、章节清单、审计结果、未解决的非阻断建议和验证覆盖说明。说明所用模型/宿主、是否独立审稿，以及样本覆盖。不得用模型自评推导市场表现或“必然优秀”。
