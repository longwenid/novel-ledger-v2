# Skill 流程图
何时读：先用图看懂派工、单章写审与首读冻结的整体关系。

下图展示主控派工、引擎校验与返修的关系；调度细节见 [runtime](runtime.md)。

无人值守统一单章写审：一个新的执笔 agent 写一章，一个新的独立综合审稿 agent 完成本章的读者与事实核验，通过后再写下一章。滚动章纲和跨章复审独立运行；材料和返修按需出现。旧 v2 项目自动备份升级，当前冻结任务完成后切入同一流程；见 [runtime](runtime.md)。

## 主流程

```mermaid
flowchart TD
    A[作者约定与已授权目标] --> C[主控 advance 取唯一任务和恢复点]
    C --> D{任务类型}
    D -->|规划或材料| E[规划未来 5～6 章或按需准备]
    E --> C
    D -->|执笔或返修| W[新的执笔 agent 只处理当前章]
    W --> S[提交正文、摘要与自查后结束]
    S --> C
    D -->|本章综合审稿| R[新的独立审稿 agent 先只读正文]
    R --> F[冻结首读；同一审稿者和 task 解锁资料]
    F --> V[核验 facts 与 reader；一次提交后结束]
    V --> Q{两类检查和程序校验有效？}
    Q -->|通过| K[原子入库；允许接续下章]
    Q -->|具体缺陷| X[本章有界返修；改稿后重新独立首读]
    Q -->|格式或证据错误| Z[当前任务修正回执；不推进]
    K --> C
    X --> C
    Z --> V
    D -->|十章、卷末、修订或全书复核| B[独立审稿会话按完整覆盖范围连续复核]
    B --> C
    D -->|首章定调| U[作者 approve]
    U --> C
    D -->|目标完成或预算耗尽| H[报告真实进度或阻碍并保留现场]
```

主控在 Worker 真实结束后使用 advance --after 核对提交。首读解锁不是另一次派工；宿主身份未知时不宣称历史隔离已验证。

## 局部返修与重设计

```mermaid
flowchart TD
    A["审稿发现具体问题"] --> S{"有能力标记的数字字面笔误<br/>事件与结算均不变？"}
    S -->|"是，合成稿两类均通过"| T["同次独立审稿提交数值补丁<br/>原子入库并继续审后文"]
    S -->|"否或仍有其他缺陷"| B{"只影响局部，且无需整章重排？"}
    B -->|"是"| C["局部修复：提交段落补丁<br/>保留其余正文"]
    B -->|"否"| D["整章返修"]

    C --> E["新的独立审稿 agent<br/>复核完整新章的两类检查"]
    D --> E
    E --> F{"通过？"}
    F -->|"是"| G["入库，继续下一项任务"]
    F -->|"否"| H{"已用完两轮返修？"}
    H -->|"否"| B
    H -->|"是"| I["重设计并重写一次"]
    I --> J["重新综合审稿"]
    J --> K{"通过？"}
    K -->|"是"| G
    K -->|"否"| L["保留现场，报告阻碍"]
```

十章复审按已入库章号触发，独立于执笔会话；全部分段审读完成后再综合复核。

具体操作与约束以 [运行与调度](runtime.md)、[审稿与完本](editorial.md)、[局部修订](repairs.md) 和 [任务协议](protocol.md) 为准。
