# Skill 流程图
何时读：先用图看懂派工、批次执笔与密封审稿的整体关系。

下图展示主控派工、引擎校验与返修的关系；调度细节见 [runtime](runtime.md)。

常规交接只需主控等待 Worker 结束，再调用 `advance --after 最后已提交任务ID`；返回下一信封后直接派工。完整结构化资料默认直接交付，常规五章按两次主控派工完成连续执笔、自查和新审稿者的逐章独立核验；长材料由一个 Worker 在同一批次内连续准备。执笔提交时由程序核验篇幅，独立审稿先冻结首读，再一次提交事实与读者两类检查。准备与返修按任务需要出现。

## 主流程

```mermaid
flowchart TD
    A["作者确定题材、主线、终局和篇幅"] --> B["初始化新小说项目"]
    B --> C["主控 advance<br/>核实提交、取任务并保存恢复点"]

    C --> D{"任务类型"}

    D -->|"设计／规划／材料准备"| E["新子 agent 完成任务或同批材料<br/>章节计划一次准备 5～10 章"]
    E --> C

    D -->|"执笔／返修"| F{"当前执笔会话还能复用？"}
    F -->|"未达复用上限，且卷、分支与上下文适合"| G["续派当前执笔 agent"]
    F -->|"达到上限或需要更换"| H["新建执笔 agent"]
    G --> I["读取最新输入<br/>逐章连写最多五章并自查<br/>返修重核后文承接"]
    H --> I
    I --> J["提交候选稿<br/>程序校验合成全文篇幅"]
    J -->|"同批仍有候选章"| I
    J -->|"批次或角色结束"| C

    D -->|"综合审稿"| K["新建独立审稿 agent<br/>先只读整批正文<br/>逐章冻结首读体验"]
    K --> L["核对事实与读者体验<br/>一次提交两类检查结果"]
    L --> M{"两类检查通过，且程序校验有效？"}
    M -->|"是"| N["正文、事件和摘要原子入库"]
    M -->|"审稿发现实质问题"| O["安排局部返修、整章返修或重设计"]
    M -->|"回执格式、证据或版本无效"| V["修正回执或刷新任务输入<br/>保留候选稿，重新核验"]
    N -->|"同批下一章"| L
    N -->|"批次完成"| C
    O --> W["保留后续候选正文<br/>失效候选事件与承接资格"]
    W --> C
    V --> C

    D -->|"十章／卷末／全书复审"| P["新独立审稿 agent 连续处理<br/>分块举证与各范围综合判断"]
    P --> Q{"复审通过？"}
    Q -->|"同版本仍有复审任务"| P
    Q -->|"复审运行结束"| C
    Q -->|"否"| R["从最早受影响章建立修订分支"]
    R --> C

    D -->|"首章等待定调"| S["作者认可首章"]
    S --> C

    D -->|"授权目标完成"| T["汇报进度与全书视图<br/>完本目标须通过最终验收"]

    C -.->|"作者暂停或无法自行解决的阻碍"| U["保存恢复点并报告"]
```

## 局部返修与重设计

```mermaid
flowchart TD
    A["审稿发现具体问题"] --> B{"只影响局部，且无需整章重排？"}
    B -->|"是"| C["局部修复：提交段落补丁<br/>保留其余正文"]
    B -->|"否"| D["整章返修"]

    C --> E["新的独立审稿 agent<br/>复核完整新章的两类检查"]
    D --> E
    E --> F{"通过？"}
    F -->|"是"| G["入库，继续下一项任务"]
    F -->|"否"| H{"已用完两轮返修？"}
    H -->|"否"| B
    H -->|"是"| I["重设计并重写一次"]
    I --> J["重新综合审稿"]
    J --> K{"通过？"}
    K -->|"是"| G
    K -->|"否"| L["保留现场，报告阻碍"]
```

十章复审按已入库章号触发，独立于执笔会话批次；全部分段审读完成后再综合复核。

具体操作与约束以 [运行与调度](runtime.md)、[审稿与完本](editorial.md)、[局部修订](repairs.md) 和 [任务协议](protocol.md) 为准。
