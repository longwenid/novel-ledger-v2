# 连续性与修订

## 数据边界

全书与分卷设计也保存在同一 SQLite，但始终属于未来计划。使用 [分层设计](design-and-brief.md) 的版本和失效机制管理，不把场景任务书中的站位提案当成已发生动作。

项目的 `novel.sqlite3` 保存作者约定、计划、正文版本、事件、审稿回执及任务状态。`work/<task_id>/` 是候选输入输出；`export` 生成供阅读的 Markdown。编辑导出文件不会影响正式数据；修改请求要通过 revise 重新提交。

稳定实体 ID 不随姓名变化。`entity` 登记首次出场，`alias` 登记化名/称号；需要合并两个已存在实体时先停下审查历史，首版不提供静默合并。伤势、生死、能力条件、动机变化和关系使用 `state`，属性名在项目内保持一致。关系建议 `relation:<对方ID>`，涉及空间行动的项目，人物位置和独一物品归属统一用 `placement/move`；计数物品用资源流水。未采用地图的旧项目可保留原位置属性，但不能与地图维护两份事实。

反复使用的场所及稳定特征见 [空间与稳定事实](spatial-continuity.md)：固定房间、办公室用途、楼层房号、出口和站位分开保存；搬迁须有变更事件，生日等固定事实不能当动态状态覆盖。

作者约定可初始化人物/资源；后续每项事件绑定章号、精确引文和字符位置。角色的 `knowledge` 单独记录 topic、claim、stance、source；错误信念不是世界事实。

人物小传与表达习惯是带版本的设计/解读，不是新事实。重要成长使用 character_development 保存变化与原因的正文证据，并触发相关档案重审；来源被历史修订移除时重新准备，见 [人物档案](characters.md)。

## 资源

所有数量写十进制字符串。`resource` 记录资产、单位、来源、去向、数量、两侧期初和理由。转移必须同单位守恒；外部获得或消费可有一端 null，但仍需要正文证明来源或用途。不能借 null 绕过资源不足。

首版不自动猜测单位换算。换算须在世界约定中明确，用同一正文证据下的“消耗旧单位＋获得新单位”两条事件表达，由事实审稿核对汇率和余数；程序分别验证两条流水，不能声称机器证明了换算语义。

不可量化的“所剩无几”“疲倦”保持叙事状态，不擅自填数。复活与不可逆伤势改变需要规则、来源和代价；`alive:false→true` 必须写 `exception_reason`，审稿仍需核实。

## 伏笔与承诺

hook 初始 `open`，保存首次证据、预计最迟回收章、重要性；后续可兑现 `paid` 或在正文交代取消 `closed`。延期必须给理由，同一钩子最多两次，之后应重审设计。程序能验证状态和引用，不能证明读者获得满意兑现。

重要性在埋设时明确；不能临近完本把重要伏笔改成不重要来绕过验收。未回收但刻意留下的开放问题应一开始就归为非核心，并符合约定；核心悬念不能靠声明“留白”逃避。

## 检索与工作包

`recall --entity <ID/姓名/别名>`；`--topic <topic/hook/asset/key>`；`--query <文字>`；用 `--start/--end/--offset/--limit` 控制范围。`--chapter N` 查询完整有效正文，超大结果分页；`--contract` 返回创作约定；`--state` 返回派生状态用于排查，不常规整包注入。

章计划 `dependencies` 钉住必要历史全文，`entities/topics/hooks` 选择工作材料。历史过大时先对冻结全文分批准备，再把带精确来源的结论交给当前任务。近章摘要、提炼记忆和最近相关事件按容量规则选入；omitted 告知可选材料省略类别与数量。疑点用 material/recall 定向核查，或提交 context_more 分批补充。不能把未选入当作不存在，正文和事件不会因为上下文规则删除。

默认 48000 字符分为输入、输出、补读和宿主预留，不等于 token 数。按宿主真实窗口校准，独立核查主控会话和 worker 历史。具体计量、扫描归并协议、补读分页及安全交接见 [长历史与有界上下文](context-runtime.md)。

## 修订和恢复

`revise --from-chapter N --reason ...` 从最早受影响章建立候选分支。系统复制未改前缀，按新稿重建其后事件、摘要、审稿和记忆；后续计划在重新写作前要核对因果，必要时在正文重设计任务中调整。修订完成并复核后，单一事务切换正式分支。

原分支始终留存；失败可 `revise --discard` 丢弃候选，恢复正式分支。`config --key published_through --value N` 冻结已经对外发布的正文，边界只前进；导出不等于发布，系统不自动上传小说。

候选局部修改可用 [版本补丁](repairs.md)，原稿不变的后续章可复用字符而不重复输出，仍重建事实、摘要及审稿。原候选以 SQLite 不可变快照保存，candidate 命令按范围读取；不能把它当已发生事实。

恢复先 status、audit。完整性坏了不能靠重写摘要掩盖；保留数据库，使用可信备份重建，首版不提供猜测式修库。普通中断从同一 pending 任务恢复；过期或取消任务结果被拒绝。
